# Session-authority `None` arms (C07)

> **Status: audited 2026-10-08.** Every optional read of a session-owned authority names what its
> `None` means, or was converted to a required read. `scripts/check_session_authority_none_arms.py`
> holds this table to source: a new optional read with no row fails, and so does a row whose
> function no longer reads one.

## What this is for

C03 moved the checkpoint coordinator (`SessionCheckpointState`) and the room memories
(`LastCutsceneRoom`, `LastQuestRoom`) onto the `SessionRoot`, so the question *"is this authority
allowed to be absent"* finally has a place to be asked. It is **not** a campaign to remove the
~780 `Option<Res<_>>` parameters in the tree: most read things that really are optional. It is
the audit of the readers of the **canonical** authorities, one row per function, in a closed
vocabulary:

| class | meaning |
|---|---|
| `reduced-composition` | the reader's plugin does not install the authority, so a composition that omits the installing plugin is a *supported* shape and the `None` arm is its behavior |
| `lifecycle-remainder` | absence is a moment in the session's life (before activation, after teardown, no operation outstanding), not a composition |
| `presentation` | a view; with nothing to read there is nothing to show (`ambition_render/`, `ambition_sim_view/` and `game/ambition_app/src/dev/` are classified by prefix, 42 more functions) |
| `refuses` | absence is an invalid composition and the arm refuses |

A `None` arm that fits **none** of these is the finding: the read is converted to required (the
probe is to convert it and run the lanes; Bevy's validation panic names the system).

## What the audit found

* **Twelve reads were converted to required** because the plugin that registers the reader also
  installs the resource, so the `None` arm was unreachable by construction and only existed to let a
  fixture skip an `init_resource`: `capture_minted_item_baseline`, `capture_owned_items_baseline`,
  `forget_bag_records_at_checkpoint`, `keep_the_bag_records_the_restore_keeps`,
  `start_the_item_domain_fresh`, `retract_mints_of_retracted_boss_defeats` (all
  `ItemCheckpointHorizonPlugin`), `forget_boss_defeats_on_a_fresh_run` (boss plugin),
  `record_consumed_pickups` / `record_ended_occurrences` (features plugin), `restore_occurrence_baseline` (the lifecycle horizon plugin, which now also installs the ledger it reduces),
  `forget_scheduled_returns_on_restore` (features plugin) and
  `request_impact_hitstop_on_resolved_hits` (combat plugin). One fixture needed its resource
  installed (`only_a_taken_authored_never_pickup_is_remembered_as_consumed`); that is the shape of
  the finding, not a regression.
* **Three of those twelve are `Option` again, for a lifecycle reason (C03 family 7, 2026-10-08).**
  The four checkpoint baselines are `SessionRoot` components now. `capture_minted_item_baseline`,
  `capture_owned_items_baseline` and `start_the_item_domain_fresh` (and the lifecycle captures
  beside them) read the baseline as `Option<SessionWorldMut<_>>`, because a required `Single`
  skips the whole system when no root is live: the commit message would then wait unread and be
  charged to the next session's checkpoint. Their `None` means "no live root", so they are
  `lifecycle-remainder`.
* **The scan did not see a qualified `Option<..::SessionWorldRef<_>>` until 2026-10-08.** The
  pattern matched only `Option<SessionWorldRef<` with no path before the alias. With the path
  allowed it found eight older optional reads with no row (perception, two spawn roads, summon,
  the Yarn run condition and four Smash match systems). They are rows now.
* **`ActiveSessionScope` has two absences, and the code treats them differently on purpose.**
  `SessionSpawnScope::for_optional_active_session` says it: an *absent* resource means the host
  installed no `SessionScopePlugin` and spawns process-resident; a *present* resource with no
  current scope means no gameplay experience, and gameplay-owned spawning sleeps. 26 functions
  outside the presentation crates read it optionally. Whether *absent* is a supported profile or only
  a fixture convenience is a question about named compositions, so it is **A9's**
  (`headless body/world` must state whether it installs `SessionScopePlugin`).
* **A9 added readers to the table.** Omitting dialogue and bosses turned the narrative
  ledger's release, the room-transition finalizer, `space_the_talkers` and the interaction system's
  dialogue dispatch into `Option`s (and `rebuild_dialog_view`, which is presentation), and the
  durable-room ledger moved from the held-items plugin to `LifecycleCheckpointHorizonPlugin`, which
  is why its readers' reasons name that plugin.
* **Cross-plugin readers are `reduced-composition`, honestly.** The checkpoint offer
  (`session/checkpoint.rs`) reads baselines installed by four other plugins, so each is `Option`; that
  is the point of the `ItemCheckpointHorizonPlugin` / `LifecycleCheckpointHorizonPlugin` split, and
  `pin_lifecycle_inputs` is the one arm that *refuses* (half a pair).
* **The checkpoint coordinator's readers are `lifecycle-remainder`.** After C03 the accepted restore,
  its outcomes and the abandoned note are `SessionRoot` components; `session_world_component` is
  `None` only when there is no live root, which is a lifecycle fact and no longer a composition one.
