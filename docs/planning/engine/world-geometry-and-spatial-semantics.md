# World geometry and spatial semantics — deferred trigger

**State:** DEFERRED. Do not schedule a broad spatial-unification campaign from
this file.

Durable spatial doctrine is now in
[`../../architecture/spatial-model.md`](../../architecture/spatial-model.md).

## Current finding

The earlier investigation established two different facts:

1. the world-boundary mechanism was already generic; the genre-specific problem
   was naming. The shipped API now uses axis-role `WorldEdgeMargins` rather than
   platform-fighter blast-zone vocabulary;
2. `BlockKind` still mixes several surface-semantic axes, but a complete Mary-O
   room could be authored without needing a combinatorial surface species.

Therefore the current enum is not evidence for a large redesign by itself.

## Reopen only on a demonstrated customer

Promote a focused slice when one of these occurs:

- a new surface requires crossing existing contact/traversal/motion/affordance
  axes and the only alternative is another combinatorial enum species;
- a second substantial moving/dynamic-geometry customer cannot use the current
  kinematic-world object contract;
- several spatial-zone domains repeat enough stable identity/provenance/query
  plumbing that one shared lower-level primitive removes real duplication;
- inspection/authoring is blocked on the lack of a common geometry descriptor;
- an external/provider game is blocked by a closed reusable-engine spatial
  switch.

When a trigger fires, solve the demonstrated shared substrate and preserve typed
domain semantics above it. Do not assume water, gravity zones, loading zones,
camera zones, stage boundaries and collision surfaces need one universal runtime
type.
