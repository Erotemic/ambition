## Headline — "a demo can have two rooms" (≈12h)

**Why this one.** `RoomTransitionRequested` has exactly one consumer in the tree
(`game/ambition_app/src/app/world_flow/room_transition_loading.rs`), registered
only by `ambition_app`. The demo apps do not depend on `ambition_app` — that is
the demo gate — so **no demo can move between rooms**. It is why Mary-O's secret
vault had to be dug into the *same* `RoomSpec` and why
[`demos/super-mary-o.md`](demos/super-mary-o.md) says a room-graph secret "would
have been dead in the demo's own app". It is a direct hit on the north-star
oracle (another platformer, no core edits), and it is the *same move* §2.5
already proved for `RoomReplayRequested`: the blocker is a MODULE, not a
dependency — `room_transition_loading.rs` names `render` exactly once.

`demos/super-mary-o.md` lists "additional planned levels — now unblocked" and
the V1 design names an underground variant and a moving-platform level. This
headline delivers the seam and the level that proves it.

## Medium A — the transformation moment (≈5h)

Jon listed this twice, for both demos:

> "In mary-o we need a 'growing' animation when she grows or transforms. In
> single player this might request that time around the transforming character
> slows down as an effect, but in a multi-player setting the time slow needs to
> be agreed upon by all players."
> "Similarly to mary-o sanic needs the transform animation, probably SFX."

One reusable engine beat, not two demo hacks: an authored **transform beat** on
the worn-identity edge — pose pin for its duration, i-frames, and a clock-scale
request through `ClockScaleRequest` (never a direct `time_scale` write, per the
time-domains rule), so the multiplayer agreement is structural rather than
promised. Mary-O's transform SFX already fires on the tier edge
(`sync_grown_form`); this hangs the animation and the time dilation off that same
edge, and Sanic's `sync_super_form_traits` edge gets it for free.

Ships BLIND for feel; the state machine is headless-testable.

## Medium B — "Choose Game": the title screen (≈4h)

Jon's longest observation. Today `basic_presentation.rs` draws 24/28px text with
keyboard-only selection: mouse-over does nothing, the touch menu icon does
nothing, buttons are not touch-sized, "Play" should read "Choose Game".

- pointer + touch hit targets on launcher rows (hover state, real button sizes),
  through the participant input path — the shell reads no raw devices;
- type scale up on the title and footer;
- a **global** settings surface reachable from the title (audio mute first),
  owned by the shell as a small IR that Ambition *extends* for its in-game
  system menu — Jon's explicit shape. Not kaleidoscope (lunex has no wasm, per
  his web note).
