- **Shield+Attack stopped throwing a held item.** The portal input adapter spent
  `melee_pressed` the moment it emitted `DropPortalGun` — before establishing
  that a drop would be accepted. `drop_portal_gun_system` answers only
  `(With<PortalGun>, Without<HeldItem>)`, so a body holding an axe lost the press
  to an action that was then refused. Likely introduced by D60's *"the adapter
  spends the press it answers"* fix (2026-08-10); the mistake was spending a
  press it does NOT answer. ⇒ **an action spends the input edge where it
  COMMITS.** The adapter is read-only w.r.t. `ActorControl` now; the drop and the
  FIRE (also refusable — `resolve_portal_fire_intent` rejects an inactive gun)
  each spend it themselves. ⭐ that removed an ordering question instead of
  answering one: drop and throw are mutually exclusive by `Without<HeldItem>`.
- **The F1 live-strike box shuddered** (⚠ this entry describes the FIRST,
  partial fix; the coherent one is D116 M2a). The overlay drew `strike.volume` —
  authoritative TICK geometry — beside a body resampled on the FRAME clock. Not a
  missing `.after(PresentedPoseSet)` edge; the overlay already had it. The read
  model publishes `owner_anchor` with a doc naming this exact shudder, and
  `unauthored_volumes.rs` already used it. ⇒ `presented_strike_volume` +
  `presented_strike_owners` in `ambition_render`, shared by both overlay hosts;
  world-anchored strikes deliberately do not move. Ancestor: the 2026-08-09 D72
  switch of F1 to `CombatGeometryView` (`aa52b3cce`) — finished, not reverted.
- **"Press reset and start again" rebuilt the room with the boss still cleared**
  (⚠ this repaired the PERSISTENCE ordering; the boss then came back inert, which
  was a different fault entirely — see the retest below).
  `(ContentDialogueFollowupSet, ContentRoomReplayResetSet).before(consumer)` is a
  bare tuple — **no edge between the two**. Measured order was `["reset",
  "followup", "applied"]`, so the reset read no request, did nothing, and the
  rebuild used the stale persisted record. Ancestor: the 2026-07-21 replay-consumer
  extraction (`cf5095576` / `7743d224f`). ⇒ `.chain()` on
  `ContentDialogueFollowupSet → ContentRoomReplayResetSet → RoomReplayApplied`.
  ⛔⛔ **the comment above it already CLAIMED this order** — a tuple reads like a

## Standing continuation rule

**This file is a continuation LEDGER, not a terminal checklist.** There is no
"the queue is empty, therefore stop" state: an empty executable list is a signal
to re-measure HEAD and refill, never a completion condition.

When the executable rows above close, **do not stop**. Re-read HEAD and promote
the next highest-value verified card from [`tracks.md`](tracks.md), a new direct
maintainer direction, or a reproducible maintainer observation.

Prefer in order:

1. Ambition flagship needs that create reusable engine capability;
2. Engine-1.0 ownership/composition/authoring work;
3. serious secondary game/acceptance pressure such as Smash or TwinTrack; and
4. deferred/trigger-based work only when its trigger is present.

Do not add meta-work merely to keep the queue nonempty. The queue continues by
finding real product or architecture work, not by manufacturing process.
