# The 72-hour queue — continuing execution ledger

**This file is the SPINE and the ledger `scripts/goal_guard.py` reads.** It is
intentionally self-replenishing. The literal open marker `▢` appears in this
header as well as on executable rows, so the guard never interprets an empty
snapshot of the queue as permission to stop.

The operating rule is simple:

> **Finish work, then promote the next highest-value verified item and keep
> going. There is no “the queue is empty, therefore stop” state.**

Document roles:

- **this queue** owns current execution order;
- [`tracks.md`](tracks.md) is the standing reservoir from which new work is
  promoted;
- focused plans own technical design and acceptance criteria;
- [`JONS_OBSERVATIONS_BUGS_AND_ISSUES.md`](JONS_OBSERVATIONS_BUGS_AND_ISSUES.md)
  owns direct maintainer observations;
- [`awaiting-maintainer-decision.md`](awaiting-maintainer-decision.md) owns work
  that cannot advance without a product/feel decision;
- completed investigations and migration evidence belong in `docs/archive`, not
  in this live ledger.

Before starting any row, inspect HEAD and confirm the named gap still exists.
When a row closes, remove its historical case file from this ledger rather than
leaving a second copy of the implementation history here. If the history is
worth retaining, archive it. Then promote another verified item from `tracks.md`
or the maintainer-observation file and continue.

The full pre-prune queue, including the closed D0–D114 investigation history,
is preserved at
[`../archive/planning-superseded/2026-08-13/queue-72h-2026-08-08-pre-semantic-prune.md`](../archive/planning-superseded/2026-08-13/queue-72h-2026-08-08-pre-semantic-prune.md).
