## Verified source observations

- `game/ambition_app/tests/` has 283 Rust files, totaling 5,842,958 bytes. The top 20 files account for 42.9% of those bytes; the top 50 account for 62.2%. These are byte measures, not test-body line counts.
- `smash_ride.rs`: 3,259 lines, 14 test functions, with 14 calls to `build_visible_app`, and 13 repetitions of the same 8-line match-live polling block. Strong fixture-extraction candidate, not a test-deletion candidate.
- `versus_stage.rs`: 3,168 lines, 32 tests; a route-launch-and-wait block repeats at least 12 times. Check distinct readiness requirements before consolidating.
- `smash_in_the_host.rs`: 8,815 lines, 76 tests; repeated game-route start/wait blocks. Retain real-input coverage; consolidate setup.
- `a_bag_changed_mid_window_reaches_the_save.rs`: 4,105 lines, 40 test functions, 14 actual ignored probes with diagnostic/print-only descriptions. Some are useful for unresolved issues. Review individually, not by blanket deletion.
- `rollback_coverage.rs`: 3,161 lines, 23 tests; deliberately poisoned failure controls check that rollback coverage instruments catch unregistered state. Protect these.
- `canonical_reconstitution.rs` and `shell_host_lifecycle.rs`: important cross-lifecycle contracts; prioritize preserving their assertions and premises.
- `docs/concepts/test-placement.md` says `ambition_app/tests/` contains 150 files; that count is stale relative to the examined tree.

## Proposed triage

1. **Consolidate mechanics, preserve assertions**: `smash_ride.rs`, `versus_stage.rs`, `smash_in_the_host.rs`, `an_edit_reaches_the_shipped_game.rs`. Compare before/after test names, features and focused passes.
2. **Review for retirement**: ignored `probe_*` diagnostic experiments, completed one-off bisection artifacts, historical measurements. Keep opt-in tools still needed for open regressions.
3. **Compare behavioral coverage**: group similar tests by system, preconditions, mutation and expected invariants. Source similarity alone cannot prove redundancy.
4. **Protect**: rollback census and poison controls; non-vacuity checks; canonical reconstitution; cross-session lifetime; two-peer rollback; input-to-action wiring; composed-app schedule checks.

## How to generate the full static analysis

From the repo root:

```bash
python3 scripts/audit_test_corpus.py --root . --scope game/ambition_app --out /tmp/ambition-app-test-audit
python3 scripts/audit_test_corpus.py --root . --scope . --out /tmp/ambition-workspace-test-audit
```

Read `audit.md` for examples and `audit.json` for the complete structured inventory. No Rust source or test files are edited. The analyzer uses conservative line normalization and symbol-sequence comparisons, so evaluate findings as candidates, not instructions to delete. Its parser does not replace `syn` or tree-sitter for full Rust syntax. The full workspace scan may take longer; start with the app subset.

## Verification rules for eventual deletion

- Require an explicitly named retained test or added check for each removed behavioral contract.
- Require stable test discovery counts (unless deliberate retirement), no ignored-test activation changes, and the focused gates in `docs/recipes/cheapest-sufficient-check.md`.
- For sensitive checks, poison one expected behavior and confirm the retained test fails. The absence of tests failing is not proof of coverage.
- Never make lint-only gates a prerequisite to gathering test evidence.
